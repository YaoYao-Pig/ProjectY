# Lua 代码风格

按下列约束开发与验证；项目有 ForAI/INDEX.md 时，仅按关键词读取相关文档及必要代码。具体项目路径、接口和数据契约以项目文档与实现为准，不复制到本技能。

## 开发

- **组件引用**：尽量避免业务 Lua 直接调用 GetComponent。需要 prefab 上的 UI 组件或对象时，复用 LuaReference 的 Key；缺绑定时使用 Unity MCP 完成绑定、保存 prefab，再用 self.view.Key。LuaReference 绑定 Component；需要 UI 对象时可绑定 RectTransform，再通过其 gameObject 访问。
- 不用 Find、子节点索引或重复路径搜索绕过绑定。已有绑定直接使用，不为读取代码启动 Editor。确需新增绑定但 Unity MCP 不可用时，先说明缺少的能力，与用户沟通替代方式；不要擅自用临时 C#、手改 prefab YAML 或运行时搜索替代。
- **高内聚、低耦合**：沿用项目的职责划分、命名、生命周期与所有权。先复用已有框架；避免业务侵入通用层、重复维护状态或为个别需求塞入特殊分支。
- **尽早暴露错误**：正确流程保证存在的数据、配置、组件或系统，缺失时应在开发期通过 assert/error 或明确异常直接暴露。禁止用层层判空、默认空表、静默 return、吞异常或伪造默认数据维持运行。外部输入和契约明确允许缺失的值仍应在边界校验；不要把真正可选的数据当成必需数据。
- **性能与一致性**：关注热路径分配、重复查找/加载和监听释放，沿用项目现有模式；不写 hack，不用绕过框架契约的代码掩盖问题。确需特殊处理或偏离既有风格时，先说明原因、影响并与用户确认后实施。
- **业务准确性**：不猜测需求。先从当前指令和既有契约确认事实；仍不清楚的业务规则、边界或行为，先询问用户，等待答案后再做依赖该答案的实现。只有用户明确说“允许自由发挥”时，才可在其授权范围内自行决定需求，并说明决定；该授权不扩大测试或代理权限。

## 测试与 Editor

- 每次完成需求，默认只做与改动直接相关的最小单元测试和基本回归；不自动跑整个项目的测试套件、完整构建或平台矩阵。纯文档/Skill 修改仅检查格式、链接和规则一致性，不运行游戏测试。
- 正式全面测试前，先说明范围、成本及涉及的 Editor 操作并征求用户意见；已有明确的“允许全量测试”指令或对该测试范围的确认时按授权执行。“允许自由发挥”不等于“允许全量测试”。
- 不把启动 Editor、进入 Play Mode、另建验证工程或启动 Player 当成默认步骤。确有必要时先说明目的和范围；会扩大验证范围或打断用户编辑状态时，先征求意见。等待 Editor 必须有明确完成信号、超时和结束条件，不无限等待、轮询或反复重启。
- **纯 Lua 改动**：不主动触发 C# 编译、Unity Reload 或用于触发这些操作的 Refresh；不为了测试 Lua 而新增临时 C# 验证脚本。
- **确有 C# 改动**：集中完成修改，只在基本测试开始前主动触发一次编译；禁止边改边编译和反复 Reload。若编译失败或后续修正需要额外编译，先说明原因并与用户确认，不自行进入编译循环。报告主动触发的操作，不把 Editor 自身的自动刷新冒充可控的一次编译。
- 完成时简述实际执行的最小检查、结果和未验证部分；通过后不无故扩大或重复验证。失败时先根据现有输出定位，再决定必要的下一步。

## 子代理

- 默认由主代理完成；没有用户明确授权，不启动 SubAgent。一般开发请求和“允许自由发挥”都不视为代理授权。
- 获得授权后，单次派发最多 3 个子代理，同时活动的子代理也不超过 3 个；仅分派具体、独立且必要的工作。
- **严格禁止 SubAgent 再开 SubAgent 或继续向下委派**。主代理须在每个子任务指令中明确这一禁令及本任务的测试/Editor 限制，并负责汇总结果。
