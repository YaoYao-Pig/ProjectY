# ForAI 精简维护

1. 读项目 `ForAI/INDEX.md`、`ForAI/MAINTENANCE.md`（存在时），只展开与本次改动相关的模块。先用任务改动清单或可用 diff 确定范围，不为写文档扫描全仓库。
2. 核对关键实现，提取真正改变下一次决策的事实：职责、外部契约、所有权/生命周期、生成源与产物、入口、验证方式。纯内部细节无需记录；不重复写历史日志、代码全文或未实现规划。
3. 修改所属模块的唯一事实来源，其他模块用链接。新独立模块才建文档并加 INDEX 路由；更名、移动、删除时修正索引与入站链接，旧文档链接也需定向检索。
4. 沿用项目格式；没有约定时使用“标题 → 关键词 → 文档目录 → 正文 → 关键入口”。入口采用相对文件链接 + 符号，不用行号。索引只路由，目录只概括本文；不递归堆叠索引或创建空模块。
5. 检查链接与符号确实存在，行为描述与实现一致，未复制跨模块规则。可运行本技能 `scripts/check_links.py`，参数为待查 Markdown 文件/目录（如 `ForAI AGENTS.md README.md`）。脚本仅检查内联链接的本地文件路径，不验证锚点、符号、行为或参考式链接；失败时修正具体链接再运行。
6. 简述更新的文档、实际验证和剩余缺口。纯文档变更无需运行游戏测试；涉及代码则遵循模块验证指引，不将历史通过冒充本次验证。

项目事实留在 ForAI，本技能只维护流程。压缩重复描述，不删除关键约束；路径/行为无法核实就明确标为待核实，不猜测。
