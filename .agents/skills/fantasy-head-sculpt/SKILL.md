# 奇幻头部雕刻与变体

使用已确认的脸部风格制作真正可旋转的头部。先读 [头部制作与替换准备](../../../ForAI/Business/HeadSculpt.md)定位当前源、接口与验证边界；Blender 操作、源文件保护和 Unity 资源写入沿用 [blender-unity](../blender-unity/SKILL.md)。

## 造型与画风

- 优先沿用用户已经认可的二维或三维参考。需要探索时用 `imagegen` 制作概念；用户要求先看二维时停在该阶段，不自行把它当成建模验收。没有分阶段要求时，概念是制作过程，不自动新增审批。
- 皮肤应是一张连续的解剖曲面：眉弓接鼻梁、眼窝接颧骨、嘴唇接口周和下颌。不要用立方体眉毛、球状脸颊、独立鼻楔拼出脸。独立眼球、牙齿和头发可以作为真实的独立结构，但不能借它们掩盖皮肤不连贯。
- 先塑形，再整理低模大切面。切面要服务于眉骨、颧骨、鼻梁和下颌轮廓；避免细碎随机三角噪声，也不要只把平滑高模称为 lowpoly。纯形体与带贴图都要看。
- 小尺寸静态棋子可以把眼睛、眉毛和胡茬画在连续曲面上；交付时如实标明，没有眼球、表情或面部骨骼就不要宣称支持它们。

## 耳朵

- 人耳要有薄的耳轮、内侧软骨转折、耳屏与耳垂；检查正面、侧面及四分之三视角。避免朝正侧方突出的圆筒、厚圆环和空杯状凹洞。
- 哥布林尖耳是有厚度和内凹面的尖叶轮廓，不是圆锥或单片三角形。长度、朝向与厚度分别控制，耳根融入皮肤；大耳不能借改变头骨或头饰位置避让。
- 局部加密后保持耳根拓扑连通；少量平滑只用于消除交接折痕，不抹掉脸部的主切面。不要为了耳朵重建已通过的五官。

## 概念投射与材质

- 将生成图作为风格/投射素材，而不是把图片冒充三维结果。最终展示必须来自实际网格渲染。
- 按输出图的真实眼线、鼻底、唇线、下巴和轮廓定位 UV；提示词中的百分比不是实际标定值。正面投射在侧面渐退，后脑、耳朵和颈部单独处理，禁止采入灰白背景、别的视图或发际线外的空白。
- 材质节点与顶点色遮罩在 Blender 可用，但交付 FBX 前应烘焙成独立 albedo，并把材质接回该贴图复查。保留可编辑投射源和便携贴图；检查贴图确实随源文件打包或以相对路径存在。
- 头发保持独立，不合入皮肤。参考发型不等于已支持当前游戏所有发型或头饰组合。

## 随机与替换准备

- 从不可变基准网格计算形态增量，避免在上一次随机结果上反复变形。种子、参数顺序、取值范围与算法一起保存；浏览器/Blender 的同种子结果应一致。
- 将可变面相与固定接口分开：颈根、Head 参考姿势、头饰包络不随捏脸漂移。参数要真正改变几何，不能只改标签或肤色。
- 检查极值组合及若干固定种子；至少验证有限坐标、颈根零位移、权重归一、单一皮肤连通分量与无开边。范围检查不能替代穿模的视觉检查。
- 对接旧角色时复制现有参考骨架，不重建或重排骨骼。先核实当前 importer 对材质、贴图、形态键和 module ID 的实际处理，再判断能否直接替换；不能仅凭 FBX 存在就说“无痛接入”。
- 骨骼同名不代表绑定有效。头部 FBX 可只导出实际变形链，再映射到完整游戏骨架；不要放宽 bind pose 误差阈值来接受空权重骨骼错误。导出朝向与形态法线须用真实 Unity 视图验证，本批配置见模块文档。
- 追加随机面容时用新 ID，保留原 ID 与已保存外观。彩色脸贴图要与身体肤色联动，不能给有肤色的 albedo 再直接乘一次完整 Skin 调色板。
- 只有源资源/样品任务时，产物留在美术源与暂存目录。正式目录、角色存档、身体和装备不属于自动修改范围。对接工作若有明确授权，再遵循项目开发约束实施最小改动。

## 验收与交付

给出实际头部对照、耳朵近景和可复现参数预览。保存 `.blend`、带形态键的 FBX、贴图及源/模块映射。FBX 导出应保留形态键，不能套用会破坏它们的普通静态 modifier 烘焙流程；重新导入一次检查骨骼和形态键仍存在。

说明哪些是 Blender 源检查、浏览器检查或 Unity 检查。未接入游戏的随机预览，不得描述成游戏已经具备自由捏脸。
