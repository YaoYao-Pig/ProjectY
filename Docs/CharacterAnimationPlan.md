# 角色动作与免费动画适配方案

## 当前结论

已使用 Quaternius 的 **Universal Animation Library Standard** 完成首批动作接入：公共身体建立 23 骨 Humanoid、配置 Unity Avatar，保留现有低多边形身体和装备。运行时 `PawnRig` 已绑定动画，资源入口为 `Assets/DynamicAsset/PawnAnimation/PawnAnimations.asset`。

原 `PawnLowPoly/Models` 的静态模型没有覆盖；独立动画源位于 `Art/PawnAnimation/Source/PawnHumanoid.blend`。公共身体、裤腿和靴子使用蒙皮，武器及硬质附件跟随骨骼挂点。运行时 `PawnEquipmentView` 在有动画绑定时停止旧的刚体手臂摆放。

## 骨架与装备契约

使用一套约 23 个基础节点的骨架：Root → Hips → Spine → Chest → UpperChest → Neck → Head；左右 Shoulder → UpperArm → LowerArm → Hand；左右 UpperLeg → LowerLeg → Foot → Toes。手指骨按实际网格需求添加。T Pose、米制单位、角色朝向和关节位置统一；四类队员和人形敌人共享骨架契约。

- 身体与跨关节的衣物使用蒙皮。保留硬边轮廓；对硬质部件使用单骨权重，对肘、膝、肩的连接处做小范围权重过渡。
- 武器、盾、头盔、胸甲等硬质附件使用显式骨骼挂点。裤腿、靴子若跨关节，需要蒙皮，不能继续整件固定在旧世界坐标。
- 保留 `PawnPartTable`、装备实例和改装规则；给显示资源增加绑定好的骨骼挂点，不让 Lua 搜索骨骼名称。
- 双手武器由主手骨驱动，副手 IK 对准武器提供的 GripTarget；双持使用独立左右手姿态。法杖、弓、枪和大剑各自配置姿态覆盖。
- `PawnEquipmentView.RenderPose` 与 Animator 不能同时改写同一条手臂。迁移后它负责装配、弹匣显隐和挂点效果；骨骼姿势交给 Animator／IK。

Unity 的跨模型 Humanoid 重定向依赖正确配置的 Avatar，见 [Unity 2022.3 官方重定向说明](https://docs.unity3d.com/2022.3/Documentation/Manual/Retargeting.html)。不要求目标骨骼和素材逐字同名，但必须正确映射人体结构。

## 首轮动作范围

以下是项目的动作槽，不是未经核实的资产文件名。

| 层 | 首轮动作 | 与当前系统连接 |
| --- | --- | --- |
| 移动 | Idle、Walk、Run、原地转向 | 使用显示位移计算速度，沿现有格子路径播放 |
| 单手／双持 | 普通斩击、副手斩击、防御姿态 | `slash`、`offhand_slash` 与武器持握类型 |
| 双手武器 | 重斩、回收动作 | 按武器配置覆盖斩击槽；推进器附加效果 |
| 远程 | 瞄准、射击、换弹；弓的拉弓与释放 | `fire`、`reload`、弹匣与技能组 |
| 法术 | 短施法、长施法 | `cast` 与施法道具姿态 |
| 反应 | 受击、死亡／倒地、恢复站起 | 真实命中结果和 HP 状态 |
| 探索交互 | 拾取、打开箱子、交谈 | 搜刮成功、设施交互命令 |

先做一名角色的 Idle／Walk／单手攻击／受击／倒地验收，再扩到全部武器。缺少的免费动作明确记为缺口，优先用已授权片段调整姿态、节奏与 IK；不静默替换成付费素材。

## 播放与规则分工

1. **位置由现有探索／战斗数据决定。** 使用不带 Root Motion 的动画，`Animator.applyRootMotion=false`；不让动画把角色移出格子、穿墙或改变占格。
2. Animator 基础层用速度 Blend Tree；动作层按武器配置切换，受击层可覆盖上半身，死亡优先级最高。移动速度和步频匹配，处理脚底滑动与斜坡高度。
3. 扩展现有动作序号为只读的表现事件：动作实例、角色、目标、技能、片段槽、朝向、时长与命中时点。每个序号只播放一次；高频 HUD 快照不得重播同一个动作。
4. 第一阶段仍由现有规则计算伤害、AP、弹药、冷却和结果，动画仅读取结果。Animation Event 只触发音效、刀光、枪口和弹匣显示，不承担扣血或发奖。
5. 自动敌方行动与下一段表现等待当前表现完成，避免上一刀还未结束就进入下一人的动作；保留跳过／加速及超时释放，不能因动画丢失卡住回合。
6. 世界动作随世界暂停；角色预览单独使用预览时钟。战斗播放和 UI 人物展示共享装配与姿态资源，不共享可变 Animator 实例。

建议后续增加 `PawnAnimationSet`（武器姿态与动作槽）、`PawnActionPresentation`（混合、播放速率、命中时点、特效和声音）配置；状态仍归 C#，Lua 解释配置，`PawnAnimationView` 只播放表现。

## 实施顺序与验收

1. 核对免费 Standard 包实际动作清单并保存许可证；挑选 5 个首轮片段。
2. 在现有 Blender 源上制作统一骨架并蒙皮一名角色，检查 1.78 米身高、脚底、朝向、肩肘膝关节；保留原模型备份。
3. Unity Humanoid Avatar 验证与重定向，关闭根位移；检查行走脚滑、武器离手和肘部翻转。
4. 接入一名角色完整的“移动 → 攻击 → 命中反馈 → 结束回合 → 倒地”表现链，验证重复快照不重播、暂停恢复不跳帧。
5. 扩展四类队员、敌人与所有持握姿态；分别验证双手 IK、盾牌、副手、弹匣和模块附件。

当前已完成基础移动、斩击/镜像副手、施法/射击/换弹、受击/倒地与搜刮/交谈入口，四类主角与人形敌人共享公共骨架。战斗表现会等待移动/动作结束，空格可跳过；规则仍立即结算。动作时长、命中比例、持握旋转、播放速度等可在 PawnAnimations.asset 编辑。

最终合并了血条修正、随机待机/步态、1.5 倍战斗移动和收招修正，按本轮授权集中编译一次。在 Edit Mode 验证有效 Avatar、裤腿/靴子蒙皮、双手握点、动作历史、重复快照不重播、暂停、受击、倒地、根位移关闭及绕墙显示路径，并通过真实地牢战斗/结算回归。截图通过临时 BakeMesh 取实际变形，避免同一编辑器帧多次渲染的 GPU 蒙皮缓存。

用户指出待机穿模后，已调整步枪比例和双手握姿，并为大剑/巨剑配置单独轨迹。双手武器在收招混合期间继续保持配置握姿；换弹轨迹和步枪的手头间距也独立配置。180 帧定向检查的武器/头盔凸包最大相交深度为 0，结果见 `Art/PawnAnimation/Integration/weapon-clearance.json`；这不等于穷尽所有装备组合的碰撞测试。

待机池按持握类型限定，角色独立随机选择片段、初始播放进度、切换间隔与小幅速率差；移动在两套步态之间交叉淡化。实际 Play 验证中，战斗 HUD 可见，头顶血条按头部精确投影（误差小于 .001 像素），远镜头 alpha 为 0。四格移动实测约 7.48 米/秒，目标值 7.5，相对原 5 为 1.5 倍。未运行全量测试。

免费包没有专门的拉弓片段；弓的拉弦/释放、完整重武器专用招式、推进器特效和地形脚底 IK 尚未作为完成内容。当前大剑/巨剑用 Punch_Cross 的身体发力配合独立武器轨迹、双手握点和不同节奏；远程基础射击不等同于完整弓手动画。
