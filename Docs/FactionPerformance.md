# 大地图暂停与势力模拟性能修复

2026-10-23。针对“大地图持续低帧，暂停后仍然卡顿”的反馈，修复持续轮询和世界模拟中的重复工作。

## 定位与改动

大地图每 0.1 秒通过 `DemoBridge` 请求完整快照。暂停没有阻止该轮询，C# 每次解析后调用 `SetView`，增加 `BattleHUDRevision`，主 HUD 因而重建内容。修复前，一万格样本中 30 次完整快照耗时 1803 毫秒，平均约 60 毫秒，尚不含 C# 解析和 HUD 更新。

现在暂停地图只比较会话身份与可观察状态。未变化时返回新的 `{unchanged=true}` 小响应，C# 在读取完整快照之前直接返回，不调用 `SetView` 或增加 HUD 版本。首次轮询、用户命令、角色与坐骑、装备、叙事、金币、据点及存档状态变化仍刷新。只缓存状态指纹，不缓存完整快照，也不重复发送特效或 GM 传送标记。

势力模拟同时做了以下优化：

- 先用距离、关系、兵力、留守和补给排除目标，再计算路线与威胁。
- 获选路线用 `ApplyRoute` 直接应用；保留 `Plan(party,target)` 原接口，避免 Lua 多返回值被误当成第三个可选路径参数。
- 玩家实力按模拟分钟缓存，各势力总实力一遍汇总；沿用显式失效入口，在结算、补员与读档后更新。
- 接触检查先读取一次队伍状态，先筛完成行军格及距离，再查双边关系和可达路径。保持原队伍顺序和攻城优先级；一格接触只增加“直接边禁行”的等价快拒绝。
- 商队复用静态地图上的已查路线，每次选择目的地仍重新检查占据状态；同一快照复用据点描述。

## 实际测量

使用已有 Editor 中的独立 PreviewScene、LuaEnv、真实 C# Data 与临时存档，不进入 Play。固定种子 `20261016`、配方 `3`、10000 格、45 支队伍、19 个据点，推进 60 个游戏分钟，再构造 30 次完整快照。计时为 `os.clock` 的 CPU 时间，各方法统计包含嵌套调用，不能相加解释为总时间。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 60 游戏分钟模拟总耗时 | 15564 ms | 1129 ms |
| 单分钟模拟中位数 | 196 ms | 8 ms |
| 单分钟模拟 P95 | 443 ms | 55 ms |
| 单分钟模拟最大值 | 2123 ms | 248 ms |
| 寻路次数 | 96 | 4 |
| 寻路合计耗时 | 1516 ms | 29 ms |
| 接触检查合计耗时 | 2063 ms | 206 ms |
| 30 次完整快照合计 | 1803 ms | 473 ms |
| 稳定暂停轮询 | 每次构造完整快照 | 30 次共 10 ms，全部跳过完整快照 |

模拟总耗时减少约 92.7%。前后队伍位置、路段进度、任务、目标、交战归属、成员生命和冲突数量的结果签名均为 `b13ee424`。这证明该样本的模拟结果保持一致，不代表所有世界种子或长时间游玩的平衡性证明。

原始记录：[修改前](../Art/FactionLowPoly/Integration/performance-before.txt)、[修改后](../Art/FactionLowPoly/Integration/performance-after.txt)。这些是 CPU 数据，不是 GPU 或真实游戏 FPS 测量；主线程仍有最高 248 ms 的模拟尖峰，未宣称完全消除所有卡顿。
