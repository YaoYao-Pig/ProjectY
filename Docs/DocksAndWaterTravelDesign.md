# 码头、城市水岸与船行设计

日期：2026-10-25。状态：首版已建模并接入，定向检查通过；当前实现与操作见[码头与水上旅行](../ForAI/Business/WaterTravel.md)。本文保留设计依据和后续范围。

关键词：码头、破损码头、修复任务、临水城市、城镇水域、码头工人、付费坐船、快速旅行、购船、自由航行。

## 一 已确认的目标

1. 部分靠河、靠水的城市在大地图上有码头；码头可能破损或暂不可用，完成清敌、收集材料等任务后恢复使用。
2. 临水城市的城镇小地图实际包含水域和沿岸码头，体现城市与河湖的关系。
3. 玩家与码头工人 NPC 交谈、支付费用后，可以在码头城市之间坐船快速旅行；大地图上显示小船沿水路快速移动。
4. 玩家可以购买自己的船，在水域中自由航行。

用户随后确认“自有船可以在野外停靠”，并要求开始建模与实现。首版采用一艘整队河船、真实水路、持久停泊、码头恢复任务及公共客运；下文建议的首版规则已按模块文档落地，扩展玩法仍不属于现有能力。

## 二 玩家体验与码头状态

建议形成两条互补路线：前期通过修复码头开放城市间客运，后期购买自己的船探索水域。修复的收益应在大地图外观、城内码头和可用目的地列表上同时体现。

| 场景 | 大地图表现 | 城内表现 | 建议交互 |
| --- | --- | --- | --- |
| 正常码头 | 岸边栈桥、停泊小船，与城镇模型同时可见 | 可步行的码头、真实水面、岸边工人 | 查看航线、付费出发；具备售船服务时可购船 |
| 结构破损 | 断桥、缺失木板或倾斜立柱 | 工人留在安全岸边，断裂处不能步行通过 | 查看修复需求、接取任务、交付材料 |
| 周边受威胁 | 保留码头结构，以状态标记说明停航原因 | 工人说明威胁及任务目标 | 接取清敌任务，完成后解除停航 |
| 同时破损且受威胁 | 同时体现破损和停航 | 展示两类条件及各自进度 | 按该码头任务配置满足全部恢复条件 |

建议分别记录“结构是否完好”和“安全条件是否满足”，营业状态由条件推导。清敌与交材料可以是不同码头的不同任务，也可以组合成一条恢复任务；不能默认每处码头都需要两者。

任务绑定具体城市、码头和目标。修复为本次世界内的持久改变；完成后重进城市或读档都不再次损坏，不重复扣料或领奖。首版建议不加入随机再次损坏或敌人自动封港；后续若接入城市占领，需要另定营业规则。

## 三 大小地图共用同一处水岸

### 大地图选址

- 从城市周边的真实水格寻找岸线，记录岸上接入格、相邻可停泊水格、朝向及所属城市。仅有“河流／湖泊地貌”标签不足以证明这座城市临水。
- 候选岸线必须能从城市陆路入口到达，并满足岸边高差、水深与航道条件。悬崖下方的水面、孤立水坑和瀑布口不能生成可用客运码头。
- 并非所有临水城市都要开通客运。建议临水城市都有水岸表达；部分城市生成可用或待修复的功能码头，其余可只有小型靠泊设施。具体覆盖比例待定。
- 码头属于城镇配套设施，不挤占原有城市身份，也不以另建一座城镇来表示。同一城市首版建议只设置一个功能码头。
- 合格岸线先参与布局预留，再放建筑和装饰，避免最后把栈桥塞进房屋、道路或不可达岸边。没有合格位置时保留诊断，不把内陆城市强行改成港口。

### 城镇小地图

- 入口携带由大地图派生的水岸描述：临水方向、河岸或湖岸形态、码头身份及靠泊位置。城镇生成器使用同一描述，整体旋转时一起变换方向。
- 首版建议支持“沿城一侧的河岸”和“城边湖湾”两种布局。穿城河、双岸城区及多港口作为后续扩展；用户进一步确认有码头的一面应整体朝水：v10 使用横贯该侧、延伸至地图边界的连续水域和有起伏的自然岸线，不再仅挖局部窄湾。
- 先保留水域、岸线和码头，再布置街区、设施与民居。码头接入公共道路；既有必需设施、住宅数量、门洞、楼梯和整队通行空间继续满足原生成约束。
- 水面不可步行；码头甲板和岸边道路可步行，破损缺口不可走。桥上步行层与桥下水面分别保留身份，不能因为共享平面坐标就允许跨层移动。
- 城内建议通过码头交互登船，切回大地图展示航行；到达另一城市后从其码头安全落脚格进入城内。首版不额外制作城内驾船操控，是否需要该体验仍可单独确认。
- 大地图码头状态与城内状态都从同一份码头数据展示，不能各自抽取破损状态。重建只更新码头相关表现及通行，不重新随机整座城市。

## 四 付费客运

建议流程：走到码头工人附近 → 查看目的地、票价和预计游戏耗时 → 确认 → 登船 → 大地图沿水路行进 → 目的地码头下船。

### 航线成立条件

1. 出发和到达码头都已满足营业条件。
2. 两个码头之间存在适合客船通过的实际水路；以水格和可航行邻边寻路，不使用两座城市的直线距离代替航路。
3. 上下船接入点有效，队伍处于允许旅行的状态，金币满足报价。

建议首版只提供到达已发现码头的直达服务；是否由工人揭示未知港口、是否允许多段换乘，均留作待定。已知但停航的目的地可显示原因，不能扣钱后才发现不能走。

### 水路与速度

- “水域相连”与“可以行船”分别判断。相邻水格还需满足船型水深、通航宽度、允许落差及障碍条件；现有等水位水体编号不能直接当作航线编号。
- 瀑布边首版建议不可通航；一般缓降河段按航行规则判断，不要求整条河水位相同。不同湖泊之间没有水路时，不生成跨陆地航线。
- 客运和自有船共用水路判定。初版可采用相同小船规格，避免一套路线可达、另一套展示穿模。
- 小船沿真实水路连续移动，速度高于默认步行的具体数值留在配置中。镜头跟随、暂停和倍速沿用大地图旅行体验；快进表现与实际游戏耗时分开配置，不允许为了视觉快速而跳过世界时间结算。
- 途中按实际位置揭示水路附近迷雾，到达后才开放目的地信息，不因购买船票直接揭示整条路线和沿线城市。

### 费用与中途状态

- 建议按整队一次航程收费，价格由起步价和航路距离组成；具体计价口径、数值和航速待定。确认界面先展示完整价格和预计耗时。
- 出发时再次检查航线、码头、余额和落脚点；扣款与旅程创建作为一次提交。失败不扣款、不切换位置；重复确认不重复扣费。
- 航行存档记录已经付款、路线、当前边和边上进度；读档暂停，不重新扣费或从出发城市重走。
- 首版建议客运途中只允许暂停／继续，不能随意改目的地或在野外下船。自有船保留自主改路能力。
- 首版建议关闭水上随机战斗和陆地敌人的跨水接战；世界时钟及岸上世界活动仍继续。若要船战、海盗或中途事件，需要另行定义水上战场与返回规则，不能复用陆地遭遇直接生成陆地战场。
- 目标在途中失效时，至少保留船、队伍和已付费状态并暂停处理；返航、退款或改港规则尚未确定，启用动态封港前必须补齐。

## 五 自有船

购买船提供水域移动能力，不只是解锁另一张快速旅行菜单。建议从可售船的码头工人购买，一次性支付船价后，玩家在大地图点选可航行水格，自主规划、暂停和改变航路。

首版建议只支持一艘基础小船，承载当前整队。船是世界中的持久对象，记录归属与停泊位置；重复购买、资金不足和重复点击不能生成多艘船。耐久、维修、船员、升级、货舱及船战暂不纳入本次首版。

### 已确认：允许合格野外岸边停靠

玩家可在安全岸格与相邻船格之间上下船；岸坡、水深、障碍和陆路接通均通过规则校验。不能在悬崖、瀑布、不可达陆地停靠，也不能在半格移动中切换交通方式。

首版采用以下规则：

- 船留在最后一次停泊处；徒步离开后需要回到船边才能再次使用，不默认背包收船或远程召唤。
- 乘坐公共客船不会把自有船自动带到目的地；提供清楚的停泊位置提示。托运、召回或陆路搬船若需要，作为独立扩展设计。
- 自由航行范围是船型允许通过的连通水域，不自动穿过陆地、瀑布或不通航的浅水。不同水系之间的船只转运暂不纳入首版。
- 上下船同时更新队伍移动方式和船的位置，不能留下水上的步行队伍、两处重复船只或无法继续操作的半完成状态。
- 保存船的身份、停泊位置、当前是否搭载队伍及旅行进度；新建世界是否继承船只另行定义，首版建议与该世界绑定。
- 沉船遗址已有独立局部地图，可作为自有船探索的后续目的地。其登临点、离开后回到哪艘船及返航状态必须单独接通；现有遗址或小艇模型不代表这些能力已经存在。

### 数据归属建议

- **生成布局**：城市水岸形态、码头静态身份、岸上接入点、靠泊水格、初始状态和航道规则。保持地图快照只读，独立随机流避免新增装饰扰动其他生成结果。
- **C# 权威数据**：码头修复／安全进度、船只归属与位置、当前交通方式、收费行程与付款状态。任务和旅行通过明确接口更新，Lua 负责规则及展示投影。
- **源配置**：码头选址及模型、修复任务模板、客运票价、船型与购船价、可航行条件。具体新表及类名在实施时确定，不在设计阶段伪造已存在的接口。
- **身份**：码头通过世界内稳定城市身份与码头身份关联；NPC、任务、停泊船和城内设施共同引用，不能使用临时模型序号、列表顺序或显示名称识别。
- **版本**：新增生成规则需版本化。建议首版新建世界启用，旧档按原版本重建，不在读档时重排旧城市或给已探索街道强行挖河；若需旧档补码头，另做明确迁移方案。

实现时还需检查陆地商队、追击、护送和迷雾对旅行方式的假设。乘船不能继续保持陆地商队附身，也不能让陆地队伍因为复用新寻路能力开始走水路。

### 内容与资源

需要大地图和城内使用距离适配的完整／破损码头、小船、工人及岸边装饰。大地图以轮廓可读为主，城内以真实尺寸和可步行甲板为准，遵循[地图资源](../ForAI/Business/MapArt.md)与[城镇街区](../ForAI/Business/TownArea.md)现有约束。模型制作与原生资源接入属于实施交付，设计文档本身不代表已制作资源。

所有玩家可见名称、任务、停航原因、报价、确认及余额不足提示，实施时按[本地化约束](../ForAI/Framework/Localization.md)进入配置 `text` 字段或语言键；本文的设计说明不能直接复制为运行时硬编码。

## 七 建议实施顺序与验收

不作工期承诺。先验证跨系统所需的数据和水路，再制作完整玩家闭环。

| 阶段 | 交付范围 | 完成判据 |
| --- | --- | --- |
| 1. 水岸与航道基础 | 稳定码头身份、候选选址、水路图、生成版本及最小状态模型 | 同种子可复现；至少一组测试布局包含两个水路相通的城市和一个不通航对照；浅水、陆地、瀑布与一般河段区分正确 |
| 2. 大小地图码头 | 普通城市及王城的水岸接入，完整／破损外观、工人和安全落脚点 | 城内水岸与大地图方向、身份一致；整队能沿公共道路到码头，不能步行穿水或破口；原设施与住宅仍可达 |
| 3. 修复与付费客运 | 至少一个材料任务、一个清敌任务，以及一条可购买的真实航线 | 完成后大小地图同步开航；一次扣料／扣费，小船沿水路移动、世界时间正确推进、抵达后落在目标码头 |
| 4. 自有船 | 购买、持久停泊、水上点选寻路、暂停改路，以及最终选定的上下船方式 | 有船才能自主进入水路；无效上下船不改变状态；徒步离开仍能找到原船；不同水系不串通 |
| 5. 存档与集成收口 | 将前述各阶段状态纳入读写与版本检查，完成边界回归和视觉验收 | 修复前后、买船后、停泊时及航行中均可保存恢复；不重复扣钱或生成船；陆地旅行、城市进出和原存档不回归 |

第 5 阶段是集成验收，不表示直到最后才设计存档；各阶段新增持久数据时同步实现相应读写。

首版完成需覆盖全部四项原始目标。暂不包含海战、船只养成、天气航行、港口经济、多船管理、运河船闸和陆路搬船；这些是建议的范围边界，若要纳入需重新调整阶段与规则。

建议实施时的最小检查包括：

- 合法／非法航路与码头选址；临水但无可建岸线的城市不会生成假航线。
- 普通城、王城与内陆城的生成回归；码头修复前后不破坏街道、门口与整队落脚。
- 对应码头任务、指定敌群、材料不足、重复交付和一次结算。
- 船票不足、无效目的地、重复确认、航行暂停改路及边进度连续性。
- 自有船停泊、重新登船、购买公共船票后的原船位置及无船禁入水域。
- 航行中读档、旧档版本、迷雾揭示、陆地敌人／商队及护送边界。
