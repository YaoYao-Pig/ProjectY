# 远征营地：场景入口与操作界面设计

日期：2026-10-27。本文保留最初设计提案；后文“当前”描述的是设计时的基线。用户确认后已实施首版，实际范围、截图与验证见[交付记录](CampSceneUIImplementation.md)，当前契约见[营地模块](../ForAI/Business/Camp.md)。

## 设计方向

把营地做成固定机位的 3D 营地小景。玩家看见自己的队员、工作台、熔炉、物资箱和医务帐篷，点击设施后打开操作面板。背景仍能辨认打开营地之前的主场景，但单独虚化、压暗。关闭操作面板回到营地，关闭营地回到原来的地图视角。

这是一个具备生活感的管理界面：不要求玩家控制队员移动，不要求自由布置建筑，也不要求旋转营地或拖动物品预览模型。交互草案中的几何模型和数值用于评审布局，不是项目模型实机截图，不读写游戏数据。

## 营地主界面

### 构图

- 16:9 下，营地占中间约 80% 宽、70% 高，四周保留可见的虚化地图。使用略带侧面的俯视固定机位，起始俯角建议 35–40°；正交或长焦透视在模型灰盒阶段比较，默认先试正交。
- 后景：树木、岩石、帐篷、晾晒架，轮廓低于标题区；左右用树木形成边框，避免完整围墙封死小景。
- 中景：左侧工作台，右侧熔炉/铁砧，后侧医务帐篷，前右物资箱。四个入口的轮廓、明暗和点击区互不遮挡。
- 中前景：篝火与少量队员，留出视线通道。工具、材料和货车填充设施之间的空白，不占建筑点击区。
- 顶栏：营地名、游戏日期时间、金币、订单摘要、关闭。底部仅保留短操作提示；不再常驻五个占满宽度的菜单。
- 悬停建筑：轮廓/局部提亮，显示名称、等级和状态。可领取时常驻小标记；未建设显示基址和建造标记，点击查看建设面板。
- 开启子面板后营地压暗、建筑停止响应；子面板退出后恢复原构图。Esc 先取消拖拽，再关闭子面板，再关闭营地。

### 建筑与职责

| 场景入口 | 打开的功能 | 当前业务映射 |
| --- | --- | --- |
| 工作台 | 合成/制作、生产订单、等待、工作台升级 | 工作台 facility 1 |
| 熔炉＋铁砧 | 已有武器的锻造、重铸、成长信息 | 现有 forge 模块，仍读取工作台等级；首版作为工作台区域的第二个交互入口 |
| 物资箱/货棚 | 背包 ↔ 营地仓库、仓库升级 | 仓库 facility 3 |
| 医务帐篷 | 医疗物品制作、医务所订单、设施升级 | 医务所 facility 2；不暗示已经存在治疗/住院玩法 |

熔炉外观不等于增加第四种设施。若后续要独立的熔炉等级、配方和升级费用，需要明确调整设施配置和业务规则；本方案首版不做这一隐含变化。

### 队员表现

使用当前队伍的外观快照创建展示角色，不把正在地图上使用的 Pawn 搬进营地。按稳定角色 ID 分配固定锚点：坐在篝火边、检查武器、整理物资、站在帐篷旁。优先复用已经确认存在的 idle 动作；坐姿、锤击、整理等专项动画需盘点后补齐，不以代码假设资源存在。

展示角色不挂战斗/导航/选择逻辑，不出现脚下控制环，不参与真实产能计算。展示动作使用独立的未缩放时间；营地的暂停租约不应冻结所有装饰动画。生产订单可驱动对应工位的工作氛围，但不绑定某名队员的业务岗位。

## 合成与生产

横向两区：左侧约 26% 的独立 ScrollRect，右侧约 74% 的详情。左侧列表固定可见；滚动右侧长说明不会带走配方列表和底部操作。

右侧上半区以物品模型为主：固定展示角度、自动按模型尺寸取景、软阴影或简洁底座。右侧同时显示产物名称、数量、用途和关键属性；下半区显示设施要求、材料、金币、耗时、主按钮。不要把全部属性挤在配方行里。

- 左侧配方行：图标、名称、产量，辅以可制作/缺材料/设施未解锁状态；支持按设施或物品类别筛选。
- 材料行明确显示“需要 / 仓库 / 背包”，沿用仓库优先扣料。缺少量有数字和文字提示，不只改变颜色。
- 主按钮随状态变化：开始制作、设施生产中、先领取产物、材料不足。按钮附近展示具体原因。
- 底部固定生产区，显示当前工位订单；可展开查看其他设施订单。状态区包含剩余游戏时间、产物和领取按钮。
- “等待 1 小时 / 6 小时 / 1 天”放在生产区；显示等待将推进世界时间，不包装为现实倒计时或治疗。
- 订单完成后变为“待领取”，仍占当前设施；背包放不下时保留整个订单，给出打开仓库的入口。成功存取后返回原选中配方及滚动位置。
- 制作新武器的预览是模板外观，不预先承诺随机品质/词缀；领取时沿用真实实例生成规则。

当前“队列”实为多个设施订单的集合，每个设施最多一个订单。首版做订单带，不画出不存在的多单排队格。多单 FIFO、取消退款、批量生产、“等待至完成”都属于额外业务扩展；特别是 `CampData.Wait` 当前仅允许 60/360/1440 分钟，不能仅靠 UI 传任意剩余分钟。

## 锻造与重铸

沿用制作页的左右结构，但左边是持有的具体装备实例，而非配方。行内显示持有者/背包位置、耐久和实例区分信息，避免同名旧剑混淆。

右侧是当前装备的真实外观快照、当前与操作后的差异、成本和单一主操作。首版锻造仅对现有规则支持的两种铁剑开放，其他装备显示未支持原因或由默认筛选隐藏。预览保留当前配件、词缀与外观，不能用模板替换实际武器。

锻造/重铸现在是即时事务，不加入生产订单。成长路线、事迹、器灵放在右侧次级页签；不要删除已有能力。器灵交谈保持现有生命周期：先关营地，再开对白；未来若改成叠层对白，需要单独设计输入和暂停所有权。

## 仓库：左右双网格

主方案是左侧全队共享背包、右侧营地仓库。双方均有标题、分类、独立内容区域和容量说明；中间不放长说明栏。选中物品的简要信息在底部显示，完整 Tooltip 复用现有物品详情。

- 从一侧拖到另一侧；落点实时预览，取消或非法落点回到原处。仓库出库到背包必须使用玩家选择的落点。
- 保留现有 R 旋转、右键取消、同类堆叠规则，关闭时清理拖拽状态。左侧是共享背包，不创造每个队员一个背包。
- 右侧采用实际仓库网格，支持内部整理，位置入档；不能用格子外观包装一个不记录坐标的数量列表。
- 首版仍只接受现有可堆叠材料、弹药、消耗品、符文和模组。武器、防具、弹匣显示不可存入原因；若要“所有东西都能存”，需要新增实例所有权转移和相应存档，不在换 UI 时默默扩张。
- 建议首版保留现有 80/160/320 件容量，并额外显示真实网格空间约束。网格尺寸需根据可存物占格和物品种类验证后定，不直接把容量数字当作格数。两种约束均应可见；后续若改为纯占格容量，需独立批准规则迁移。
- 建议默认整堆拖动，失败整体保留；Shift 点击快捷转移/数量拆分可后续增加。当前菜单“每次 10 件或 1 件”是界面选择，不应变成拖拽物体与实际转移量不一致的隐藏规则。

这里需要数据改造：现有 `CampData` 只保存 ItemId+Count，`Deposit` 按同类总数消费，`Withdraw` 自动发回背包。它们没有源独立堆、目标格、旋转或仓库位置参数。必须新增按稳定堆键规划、校验、一次提交的交易接口；失败不改变任意一侧。复用搜刮的视图和落点协议，不能假装现有两个方法已经支持双网格拖拽。

旧存档迁移须对堆叠物执行确定性的合法安置并保留总数；无法安置的存档应明确拒绝或走批准的迁移方案，不静默丢物。若只想先交付更小版本，可右侧先做自动整理的物资格，但那是明确降级版本，不能视为完整双网格完成。

## 建设与升级表现

在对应设施面板内设置“升级”入口，移除独立的全屏建设列表。未建造工位点击基址打开材料、收益和外观预览；仓库零级已经可用，不能把所有零级设施统一标为不可用。

| 外观等级 | 工作台与熔炉区域 | 仓库 | 医务所 |
| --- | --- | --- | --- |
| 0 | 工具包、木桩和熄灭的基址 | 一个可使用的箱子 | 折叠帐篷与简易用品 |
| 1 | 木工作台、简易炉、铁砧和少量工具 | 箱组、木架与遮雨布 | 小帐篷、诊疗桌 |
| 2 | 顶棚、工具墙、完整炉体与材料架 | 扩展货棚、更多箱组和货车 | 更完整的帐篷、药架与灯具 |

按设施等级替换视觉变体，同时带动附属装饰密度。建筑位置与交互锚点固定，升级只扩展预留范围，不让玩家重新寻找入口。仓库升级带动箱子/货车，工作台升级带动工具和炉区，医务所升级带动帐篷和晾晒；不新增“装饰物独立升级”的玩法。

配置提议：单独的视觉资源映射保存 `facilityId + level → prefab/交互锚点/装饰组`。玩法等级仍只读 CampData。三档外观的数量需盘点后安排制作；目前仅确认已有箱子、熔炉和部分城镇铁匠铺模型，尚未验收为适用的三档营地 Prefab。

## 场景、相机和合成

推荐保留一个独立的 `CampPresentation.unity`，通过 Additive 异步加载，主场景不卸载、不重新初始化。Additive 解决资源和生命周期隔离；它本身不会自动产生模糊和画面叠加。

建议渲染顺序：

1. 主世界相机输出场景颜色，排除主 HUD；打开营地时取得一张画面并做低分辨率模糊、压暗。
2. 营地专用固定相机只渲染 CampPresentation 层，到透明背景 RT。地台和后景仅覆盖中部，外围 alpha 留出主场景；不要用不透明天空盒或全屏地板封死底层。
3. UI 合成底层世界画面、营地 RT、建筑状态标签。
4. 子面板覆盖其上，装备预览使用另一台按需渲染的物品相机，文字保持清晰。

打开营地时世界本就暂停，因此默认抓取一次主世界背景；显式等待、更换分辨率或需要更新昼夜画面时重新捕获。若之后确实需要背景云水继续动，再评估低频刷新；“主场景保持加载”不等于必须重复渲染主世界。

选择 RT 合成是为了分别控制模糊、透明和 UI 裁剪。URP 也提供 [Base/Overlay camera stacking](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/manual/camera-stacking.html)，但其本身不提供所需背景分层虚化。项目现有 Renderer 1 已服务离屏预览；营地若需要阴影和单独调色，采用独立配置，不修改所有头像/工坊共享预览的渲染规则。

落地注意点：

- 不切换 Active Scene 来驱动业务，不新建 Adventure；业务单一权威状态仍是当前 CampData、EquipmentData 与 NarrativeData。
- 独立 cullingMask、Volume mask 和射线 mask；相机可见性隔离不等于灯光隔离。营地灯采用匹配的光照层/隔离范围，校验主世界定向光不会照进营地、营地光不会污染世界。不得改共享 RenderSettings 来伪造独立场景光照。
- 保留透明清屏；URP 14 后处理的 alpha、软边、Bloom 和颜色空间须做专项实机检查，不能承诺开启任意后处理仍保留 alpha。首版优先明确可保留透明的独立 renderer，必要时用独立遮罩合成。
- UI 优先接收输入。子面板显示时不向场景射线投递；营地打开期间不向地图透传移动/交互输入。
- RT 点击坐标从实际显示矩形转换为 viewport，处理宽高比留边和缩放；不要直接把全屏坐标丢给营地相机。
- 只有一个营地总会话持有暂停与输入租约；子面板不重复开关世界暂停。关闭、Back、异常、快速连续开关和加载中取消都走同一清理路径。
- 释放 RT、预览实例、灯、事件监听和加载句柄。可缓存静态场景资源，但关闭时停掉渲染与装饰更新；读档/退出世界时完整销毁。
- 固定镜头主要验证 16:9、16:10、21:9 和较低分辨率，建筑热点不能被裁掉。宽屏扩展边缘背景，不随意改变工位相对位置。

## 实施顺序与验收

1. 场景灰盒：固定机位、四个热点、主世界背景虚化、打开/关闭和输入隔离；先验证透明合成与取景。
2. 制作与锻造：左侧独立滚动、固定模型预览、材料、现有操作和同页订单/等待。保持实例身份和单设施单订单。
3. 仓库：新增真正的仓储网格与原子拖拽事务，完成旧档迁移、非法落点、满包、同类独立堆和重复提交的定向检查。
4. 美术：换入项目模型、三档升级、人物展示与已确认的动画、音效；最后检查场景状态、成本和 UI 提示一致。

验收应直接覆盖用户操作：点工作台制作→同页等待→领取；点铁砧选择具体武器→锻造后仍是同一实例；双向拖拽→非法落点零副作用；升级→模型与热点正确；Esc 逐层返回→地图位置/暂停恢复；重复开关→无额外相机、RT 或队员泄漏。
