# 有限角色定制与网页预览方案

状态：首批模型、共用装配接口与独立网页已实施。当前事实与使用入口见 [角色定制](../ForAI/Business/PawnCustomization.md) 和 [角色工坊](../ForAI/Tools/CharacterPreview.md)。下文保留设计依据；敌群配置池、角色/背包存档与装备适配已接入；地图和战斗不存档。

## 目标

玩家和敌人共用一套 lowpoly 角色模块，支持选择或随机组合脸、体型及种族特征，包含男性与女性。Blender 保存可编辑源，Unity 保存正式资源与组合规则，网页展示这些真实资源的组合及动作。

## 已核实的基础

- Blender 当前打开 `PawnAnimation_Studio`，公共角色为 `Pawn_Human_Animated`，骨架为 `Pawn_Humanoid`。身体、头及手脚位于同一张蒙皮网格；当前没有 Shape Key。
- Unity 实际导入的 `PawnHumanoid.fbx` 具有有效 Humanoid Avatar，蒙皮引用 23 根骨骼、23 个 bind pose，当前没有 BlendShape。
- [PawnAnimationAssets.Attach](../Assets/GameFramework/Editor/PawnAnimationAssets.cs) 把动画身体装入 PawnRig，并明确绑定挂点与骨骼。运行时使用该装配后的材质绑定，不能仅导出 FBX 默认材质来代表游戏外观。
- [PawnView.ApplyAppearance](../Assets/GameFramework/Samples/Adventure/PawnView.cs) 当前替换装备插槽，对受支持的身体 ID 启用公共动画身体；它还没有脸型、种族或体型装配入口。
- [PawnAnimationView](../Assets/GameFramework/Samples/Adventure/PawnAnimationView.cs) 共用 AnimatorController、手动动画时钟和双手握点求解。裤靴蒙皮与武器轨迹按照现有身体制作，身体扩展必须考虑这些约束。
- 现有 [Web 服务管理](../ForAI/Tools/WebServices.md) 可注册新工具。角色网页应纳入这一入口。
- 当前 Unity 工程为 `D:/Program/Unity/Project Y`，Editor 处于 Edit Mode。Unity 当前场景与 Blender 场景均有未保存状态，制作与检查应使用独立作品副本及 PreviewScene。

## 已确认的首批范围

1. 人类、精灵、哥布林、龙人、兽人五族男女。
2. 保持双足人形、使用现有骨架，以脸、耳、角、肤色和体型区别种族；本批不增加尾巴或翅膀。
3. 独立网页，读取 Unity 实际导入资源的导出包。

用户已回复“按建议”。首批目录提供男女各三档体型、每族男女各两种脸、三种发型与无发；随机仅在目录兼容选项内等概率选择，敌群外观由独立配置池指定，详见当前模块文档。

## 模型与动画约束

- 以现有骨架作为基准，固定骨名、父子关系、参考姿势、单位、朝向和导出坐标。保留原源文件；新模块在独立 Blender Collection/作品中制作。
- 将基础身体与头部拆开，定义一致的颈部连接边界。头发、耳朵、角、獠牙等按实际结构制作独立模块或作为脸型的一部分；不要让脸型替换承担骨架替换职责。
- 先做离散体型预设。可在固定关节与连接边界下改变身体轮廓；如果需要明显改变四肢长度、肩宽或身高，需重新核实 Avatar、绑定姿势、脚落点、武器握点与装备适配。
- 每个模块记录骨骼映射；Unity 按映射重绑定到角色实例的同一套骨骼，检查 mesh bind pose 与目标坐标系的一致性。不能直接假设不同 FBX 的 bone 数组顺序一致。
- 接口附近的顶点位置与权重必须兼容，低多边形关节需保留足够拓扑支撑弯曲。蒙皮权重归一化、无遗漏顶点、无负缩放。
- 男女与不同种族应在轮廓和头脸上可辨认，不只更换颜色。保持当前硬边、纯色、略夸张头手及游戏观察距离下的可读性。
- 体型、发型、耳角与装备需要明确兼容关系。只有实际检查通过的组合进入随机池；不以隐藏不兼容模块或静默换回默认外观掩盖错误。

## Unity 组合与随机化

建议增加独立的角色外观描述，明确种族、性别表现、体型、脸型、发型、特征模块、颜色与目录版本；装备状态仍由现有装备系统持有。

模块目录负责有效选项、资源引用和兼容关系。玩家手选与敌人随机都输出同一种外观描述，再进入同一个 Unity 装配入口。随机函数接收种子和允许范围，按目录筛选有效组合；保存实际模块 ID 和颜色，不仅保存种子，避免目录更新后已有角色变脸。

角色生成时确定外观，随后存储并随表现快照传递；不能在重新进入视野、刷新 UI 或每次 ApplyAppearance 时重新随机。正式接入敌人前，需要明确哪些角色或遭遇使用哪些种族池。

## 网页三种交付方式

| 方式 | 资源与动画来源 | 使用条件与边界 |
| --- | --- | --- |
| Unity 资源导出包 | 从 Unity 实际导入的 Mesh、材质绑定、骨骼、外观目录和动作采样导出 | 可独立运行；浏览器负责渲染，光照和着色可能与 Unity 不同。不能把 Blender 另导的一套近似模型当作 Unity 实际资源 |
| Unity WebGL | 直接复用 Unity 装配与动画代码及正式资源 | 可独立运行；需要准备专用预览入口、确认平台支持并构建。浏览器结果仍需验证 |
| 本机 Editor 渲染 | 在独立 PreviewScene 使用实际 PawnRig 与装配入口 | 与现有 Unity 渲染最直接一致；依赖正在运行的 Editor，网页服务须处理其不可用状态 |

无论选择哪种方式，网页至少提供：种族与男女切换、有效模块选择、随机种子与随机组合、转动和缩放、动作播放与暂停、外观描述导出。模型来源路径和资源版本用于定位过期数据，资源缺失应明确报错。

独立导出包必须包含 Unity 资源依赖标识或哈希；Unity 资源更新后重新导出，网页明确显示当前包版本。若导出动画姿势，需要从现有动画装配入口采样，区分基础 Humanoid 动作与武器握点修正，不能用基础 Clip 采样冒充完整战斗表现。

## 实施顺序与最小验收

1. 确定首批种族、额外骨骼范围与网页方式，冻结可检查的首批模块清单。
2. 完成一对男女基准模块，在 Blender 检查颈部接缝、体型轮廓及关节变形；通过后按同一契约扩展已选种族。
3. 从暂存目录导入 Unity，生成明确绑定的目录与装配资源。检查 Avatar、bind pose、骨骼映射、材质及边界盒。
4. 在独立 Edit Mode PreviewScene 对每种体型与种族采样待机、行走、攻击、受击和倒地，检查开裂、异常拉伸、脚落点与手持装备。双手武器另外检查握点和头部穿插。
5. 接入网页，检查手选、约束随机、相同种子复现、动作、外观导出，以及资源过期/缺失时的明确反馈。
6. 在外观数据归属与种族池确定后接入角色和敌人实例，验证重建表现对象不改变已保存外观。

验证遵循 [项目开发规范](../.agents/skills/lua-code-style/SKILL.md)。首批资源在独立 PreviewScene 检查，详细范围及边界见当前模块文档；未构建 WebGL，也没有完成新外观的实际游戏 Play 验收。
