# ForAI 维护约定

关键词：写文档、维护、索引、分层、skill、格式、准确性。

## 文档目录

正文：读取与写入规则 / 格式；关键入口：路由与技能。

## 正文

- 阅读顺序：根 AGENTS → INDEX → 命中模块 → 必要代码。通常一篇足够；沿链接追加阅读必须有当前问题需要。不要递归展开所有链接。
- 新职责放 Framework / Business / Tools 对应目录，一职责一篇；先复用已有文档，确有独立模块再新增索引行。不建空模块或多层空索引。
- INDEX 仅路由，模块文档仅职责、外部契约、易错约束、验证入口；字段全集、长示例和历史日志保留在代码或详细参考，不重复搬入 ForAI。
- 文档事实以实际入口代码核对。只在职责、契约、路径、关键约束或验证方法变化时更新；实现重构未改变这些内容可不改文档。
- 同一事实由所属模块维护；跨模块用链接，不复制规则。新增/更名/删除文档时更新 INDEX 和入站链接；入口用文件链接 + 符号，避免易失效的行号。
- 默认索引约 30 行内，模块约 20–40 行；这是压缩目标，不以删掉必要约束换取短文档。未来方案单独标明，不混入“当前实现”。
- 提交前检查本次文档涉及的路径、符号和行为；链接检查不能证明行为正确。验证记录仅写实际运行结果，不把历史通过当成本次通过。纯文档改动无需重跑游戏测试。

统一格式（以下是示意，不直接批量创建文件）：

```markdown
# 模块名
关键词：用户词、代码符号、常见问题。
## 文档目录
正文：职责 / 约束 / 修改与验证；关键入口：相关实现。
## 正文
只写影响下一次修改的必要事实；跨模块细节链接到所属文档。
## 关键入口
- [文件名](相对路径)：应定位的符号与用途。
```

## 关键入口

- [INDEX.md](INDEX.md)：关键词路由；[AGENTS.md](../AGENTS.md)：始终可用的轻量指引。
- 配套技能 [$forai-read](../.agents/skills/forai-read/SKILL.md) / [$forai-write](../.agents/skills/forai-write/SKILL.md) 随仓库维护：前者按需读取，后者按改动维护并提供本地链接检查脚本。项目事实只保存在 ForAI，不复制进技能。
